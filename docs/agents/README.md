# AppyScript for AI Agents

AppyScript is built to be consumed by AI agents. Three integration methods:

---

## Method 1: REST API (recommended — works with any agent)

The AppyScript REST API requires no installation. Any agent with HTTP access can use it.

### Base URL
```
https://api.appyscript.dev    (production)
http://localhost:3001          (self-hosted: npx appyscript serve)
```

### Compile a program
```http
POST /api/compile
Content-Type: application/json

{
  "source": "when button_a pressed\n  say \"Hello!\"\n  show happy\nend",
  "target": "esp32"
}
```

Response:
```json
{
  "ok": true,
  "code": "# Generated by AppyScript...\nfrom applaa_robot import Robot\n...",
  "errors": [],
  "warnings": []
}
```

### Validate before presenting to a user
```http
POST /api/validate
{ "source": "...", "target": "esp32" }
```

### Simulate without hardware
```http
POST /api/simulate
{
  "source": "when distance < 30cm\n  show angry\nend",
  "sensors": { "distance": 20 },
  "maxTicks": 10
}
```

### Explain in plain English
```http
POST /api/explain
{ "source": "..." }
```

### All endpoints
```
GET  /api/health         → { status, version }
GET  /api/targets        → [{ id, name, runtime }]
GET  /api/keywords       → { keywords: [...] }
GET  /api/openapi.json   → OpenAPI 3.0 spec (machine-readable)
POST /api/compile        → compile to hardware code
POST /api/validate       → syntax + semantic check
POST /api/simulate       → run without hardware
POST /api/explain        → plain English summary
```

## Method 2: MCP Server (for Claude, Cursor, etc.)

The MCP server gives AI assistants direct tool-calling access to AppyScript.

### Install
```bash
npm install -g appyscript
appyscript mcp   # starts MCP server on stdio
```

### Claude Desktop configuration
```json
{
  "mcpServers": {
    "appyscript": {
      "command": "appyscript",
      "args": ["mcp"]
    }
  }
}
```

### Available MCP tools
| Tool | Description |
|---|---|
| `appyscript_compile` | Compile source → hardware code with full diagnostics |
| `appyscript_validate` | Validate syntax + semantics + lint |
| `appyscript_simulate` | Run without hardware, inject sensor values |
| `appyscript_explain` | Plain English program summary |
| `appyscript_hardware_info` | Sensor availability per target |
| `appyscript_list_targets` | All supported platforms |
| `appyscript_list_keywords` | Complete keyword list |

## Method 3: npm Package (for Node.js agents)

```bash
npm install appyscript
```

```typescript
import { compile, validate, simulate, explain } from 'appyscript'

// Compile
const result = compile(source, 'esp32')
if (result.ok) {
  console.log(result.code)         // MicroPython ready to flash
}

// Validate
const { valid, errors } = validate(source)

// Simulate
const ast = parse(tokenize(source))
const sim = simulate(ast, {
  sensors: { distance: 20, light: 60 },
  buttons: { a: true },
  maxTicks: 50,
})
console.log(sim.events)           // everything the robot did
console.log(sim.finalState)       // final position, expression, variables

// Explain
const explanation = explain(source)  // "When Button A is pressed: runs 3 actions"
```

## Agent workflow guide

### Step 1: Get context
```http
GET /api/targets    # know what hardware is available
GET /api/keywords   # know valid AppyScript keywords
```

### Step 2: Generate AppyScript
Write AppyScript based on what the user wants. Use the keywords list.

### Step 3: Validate
```http
POST /api/validate { source, target }
```
If errors → fix and re-validate. If warnings → show to user.

### Step 4: Simulate
```http
POST /api/simulate { source, sensors: { distance: 20 }, maxTicks: 10 }
```
Verify the program behaves as expected before presenting.

### Step 5: Compile
```http
POST /api/compile { source, target }
```
Return the generated code to the user with flashing instructions.

## Supported targets

| Target ID | Output | Use for |
|---|---|---|
| `esp32` | MicroPython | ESP32, M5Stack robots |
| `pico` | MicroPython | Raspberry Pi Pico W robots |
| `microbit` | MicroPython | BBC micro:bit robots |
| `arduino` | Arduino C++ | Arduino robots |
| `circuitpython` | CircuitPython | Adafruit boards |
| `homeassistant` | YAML automations | Home Assistant smart home |
| `esphome` | ESPHome YAML | ESP32 smart home devices |
| `nodered` | Node-RED JSON | Node-RED visual automation |

## Error codes reference

| Code | When | Fix |
|---|---|---|
| E020 | `do` calls undefined behaviour | Add `define` block |
| E021 | Variable used before `let` | Add `let varname = 0` first |
| E022 | Duplicate `define` name | Rename one of them |
| E023 | Sensor not on this target | Remove sensor or change target |
| W001 | `forever` without `wait` | Add `wait 10ms` in the loop |
| W002 | `stop` before `move` is redundant | Remove the `stop` |
| W004 | `define` block never used | Add `do name` or remove it |

## Home automation example

```appyscript
# Smart home automation
when motion detected in "living_room"
  turn on lights in "living_room"
  notify "Motion detected!"
end

when time is 22:00
  turn off lights
  set thermostat to 18
  lock front_door
end

when temperature > 28
  notify "It's too hot — {temperature}°C"
  set thermostat to 22
end

when sun rises
  dim lights to 30%
  scene "morning"
end
```

Compile for Home Assistant:
```http
POST /api/compile
{ "source": "...", "target": "homeassistant" }
```

Returns YAML to paste into `automations.yaml`.
